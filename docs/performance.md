# 성능 최적화와 로컬 컨텍스트

우선 같은 원문을 다시 읽고 모델이 다시 정리하는 작업을 줄인다. 개인 정보는 Git에서 제외된 로컬 컨텍스트로 재사용하고, 실제 입력 화면과 공고 조건은 실행 시 확인한다. 전체 지원 시간을 얼마나 줄였는지는 아직 측정하지 않았다.

## 적용 순서

| 순서 | 작업 | 현재 상태 | 확인할 지표 |
| --- | --- | --- | --- |
| 1 | 최초 자료 정리 후 JSON과 용도별 Markdown 재사용 | 구현 | 캐시 적중, 원문 조회 횟수, 컨텍스트 길이 |
| 2 | 페이지 단위 입력과 입력 전후 전체 조회 | 구현 | 전체 폼 조회 2회, 개별 대상 확인, 입력 정확도 |
| 3 | 반복되는 커스텀 위젯을 사이트 어댑터로 처리 | 다음 작업 | 위젯별 도구 호출 횟수, 소요 시간, 선택 정확도 |
| 4 | 모델·MCP·브라우저 단계별 시간 기록 | 로컬 컨텍스트 시간만 구현 | 중앙값, p95, 재시도 횟수 |
| 5 | 모델별 같은 작업을 비교하여 선택 | 미검증 | 응답 시간과 필드 매핑 정확도, 기존 값 보존 |

모델을 바꾸는 것만으로 브라우저 응답이나 위젯 대기가 줄어드는지는 별도 측정이 필요하다. Jev 모델 등 후보도 같은 프로필과 가상 폼으로 비교한다. 현재 특정 모델의 개선 효과를 주장하지 않는다.

## 재사용하는 정보와 갱신 기준

`matching.private.md`는 프로젝트·기술·지원자격만 제공한다. `autofill.private.md`는 정형 입력값과 출처·확인 상태를 제공한다. 전체 원문과 모든 개인정보를 매번 모델에 전달하는 대신 해당 단계에 필요한 문서만 읽는다.

프로필 JSON의 SHA-256과 문서 버전을 비교하며, Markdown 내용도 별도 해시로 확인한다. 프로필이 변경되거나 문서가 손상·수정되면 다음 조회에서 다시 생성한다. 원문이 외부에서 바뀌었는지는 이 검사로 알 수 없다. 사용자가 원문을 바꾸었다고 알려주면 원문을 다시 읽어 JSON을 갱신한다. 문서 생성 시각은 원문 확인 시각이나 사실 확인 시각이 아니다.

MCP의 `get_reusable_context` 또는 CLI의 `context`는 원문을 조회하지 않는다. `refresh=true` / `--refresh`도 로컬 문서를 다시 생성하는 옵션이다. 추천 점수와 입력 계획은 기존 JSON을 직접 사용한다. 새로운 원문은 현재 지원하는 Notion 조회 또는 호스트의 스냅샷 가져오기로 확인하며, 다른 자료도 호스트가 출처 있는 표준 프로필로 정리할 수 있다.

공고 접수 여부·마감·지원 조건, 현재 폼의 필드·기존 값·드롭다운 선택지와 로그인 상태는 오래된 컨텍스트를 근거로 확정하지 않는다. 필드 ID나 입력 계획을 다음 세션에 재사용하지 않는다.

## 브라우저와 모델의 다음 최적화

학교·전공 검색 등 반복되는 위젯은 관찰한 화면에 맞는 어댑터를 만들어 모델이 클릭 단계를 매번 판단하는 횟수를 줄인다. 고정 시간 대기보다 대상의 표시·활성화·응답 상태를 기다린다. [Playwright의 auto-waiting](https://playwright.dev/python/docs/actionability)은 조작 가능 여부를 확인하며, 실패 시 제한 시간 안에 오류를 반환한다. 현재 실제 위젯 속도 개선은 별도 구현·검증 대상이다.

페이지의 확인된 빈 필드는 한 계획으로 묶되, 각 대상을 쓰기 직전에 확인하고 결과를 새로 읽는다. 성능 비교에도 기존 값 보존과 미확인 값 미입력 기준을 유지한다.

모델 비교는 동일한 입력·도구·네트워크 조건에서 여러 번 실행한다. 사용자 로그인과 확인에 걸린 시간은 자동 처리 구간과 구분한다. 민감한 값이 포함된 프롬프트·화면·입력 결과를 공개 성능 로그에 넣지 않는다.

## 측정 범위

`get_reusable_context` 응답의 `elapsed_ms`는 **로컬 JSON 읽기, 지문 비교, Git 제외 확인, 문서 조회·생성**의 시간이다. `cache_hit`는 문서를 재생성했는지, `character_count`는 전달하는 Markdown의 길이를 나타낸다. 토큰 수나 전체 에이전트 실행 시간을 뜻하지 않는다.

이 지표에는 모델 응답, MCP 전송·프로세스 시작, Notion·공고 조회, 실제 브라우저 입력과 사용자 로그인 시간이 포함되지 않는다. 원문을 재사용할 때 생략되는 조회·해석 작업과 전체 시간의 관계는 실제 시나리오에서 별도로 측정해야 한다.

Git 제외 확인은 Markdown과 메타데이터를 한 묶음으로 검사한다. 같은 두 파일을 각각 검사할 때의 Git 명령 6회를 3회로 줄였으며, 제외 여부와 추적 여부는 계속 확인한다. 다음 명령은 가상 프로필을 임시 저장소에서 사용하고, 두 검사의 실행 순서를 번갈아 같은 캐시에 대해 비교한다. 기존 개인 프로필을 읽거나 수정하지 않는다.

```bash
uv run python examples/benchmark_context.py --samples 30
```

출력은 각 방식의 중앙값·p95와 캐시 적중 여부만 포함한다. 실제 사이트에서 얻은 시간이나 전체 지원 시간의 개선율로 해석하지 않는다. 임시 데이터는 실행이 끝나면 삭제된다.

가상 프로필과 임시 데이터 디렉터리로 재사용을 확인하는 명령은 [README](../README.md#로컬-markdown으로-정보-재사용)에 있다. 생성 문서·메타데이터는 Git에 포함하지 않는다.
